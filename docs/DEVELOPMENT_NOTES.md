# Development notes and provenance

ASTERION was packaged as a self-contained local prototype: source code, synthetic fixtures, tests,
documentation and visual assets were produced together, and automated local execution produced the
reference reports and test logs under `reports/`.

The synthetic expected outcomes and the scripted target policies were written in the same
development effort, though they are separated in code. This is not independent scientific
validation. Source references are documented separately in [`SOURCES.md`](SOURCES.md). No employer
code, customer data, credentials or personal documents are in the repository.

The canonical diagrams are editable vector assets generated from local layout source and checked
visually. Browser captures show the actual rendered local HTML. Generic imagery that does not match
the project design is not part of the canonical architecture. No stock imagery, font binary or
vendor certification badge is redistributed.

## Publication, 2026-09-17

The package arrived as a ZIP archive. This section records what was checked, what was changed and
why before the first push. The detailed logs are in
[`reports/verification/2026-09-17-local-windows/`](../reports/verification/2026-09-17-local-windows/README.md).

### Review before anything ran

- Read every text file in the package: source, tests, scripts, workflows, Terraform, documentation,
  schemas and the shipped verification logs. Viewed the hero, one diagram plate and one explorer
  screenshot.
- Scanned for employer and client identifiers, API keys and tokens, private keys, e-mail addresses,
  phone numbers and unpublished project codenames. Nothing sensitive was found. One line of
  `AGENTS.md` named four unpublished project codenames and was rewritten generically. The shipped
  logs contain paths from the packaging environment and were kept as a faithful record.
- Fetched every external URL cited in the docs; all nine returned HTTP 200.
- Confirmed the pinned `langgraph==1.2.10` and `langgraph-checkpoint-sqlite` 3.x exist on PyPI.

### Verification and what it found

- With `.[api,dev,agent]` installed on Windows 11 and Python 3.11.9, the suite ran 73 tests. The
  three native LangGraph tests, skipped in the packaging environment, ran and passed.
- One test failed on the first run: `test_html_escaping_and_export`. `export_dossier` hashed UTF-8
  text but wrote files in text mode, so Windows wrote CRLF and the manifest no longer matched the
  files. It now writes the exact hashed bytes. This is the only change under `src/`, and it does not
  change Linux output. After the fix, 73 passed at 94% coverage.
- The benchmark reproduced the four case studies with byte-identical evidence digests to the
  packaging run. Comparing them exposed a second Windows defect: `scripts/benchmark.py` recorded
  source paths with backslashes. It now records POSIX paths, and the only source hash that differs
  from the shipped summary is `reporting.py`.
- Helper scripts that read or wrote non-ASCII HTML and SVG with the platform default encoding now
  use UTF-8 and LF. A `.gitattributes` keeps LF on checkout, because CRLF conversion would break the
  committed dossier manifests and the recorded source hashes.
- Schemas regenerated byte-identically, asset links and SVGs validated, the shipped and freshly
  exported dossiers verified, and everything byte-compiled.
- The CLI ran both engines. A LangGraph run stopped at `PENDING_REVIEW`, and a separate process
  resumed the interrupt to `APPROVED`, with the same cells, witnesses and observations as a
  reference run. A stale digest was refused.
- A new `scripts/api_smoke.py` started the API under uvicorn, exactly as the Dockerfile does, and
  passed 10 HTTP checks.
- `python -m build` produced a wheel and an sdist. The wheel ran the demo in a fresh environment
  with only the core dependencies.
- The offline explorer was not driven interactively, because no Chromium or Playwright was
  installed on the machine. The page is byte-identical to the one the packaging run checked. A
  static check confirmed it embeds exactly the committed reports and loads nothing remote.

### Structure and documentation changes

- The packaging-time verification files and `PACKAGE_MANIFEST.json` moved unmodified into
  `reports/verification/2026-09-16-packaging/`. The new local record sits beside them, with an
  index in `reports/verification/README.md`.
- The committed reference reports were not regenerated. They remain the packaging-run record.
  Their `summary.json` therefore carries the pre-fix hash of `reporting.py`; the fresh summary in
  the local record carries the current one.
- `pyproject.toml` now requires setuptools 77+ for its SPDX licence string, and declares URLs,
  classifiers and the licence file.
- CI gained the API smoke test, dossier verification of the four reference reports, and a package
  build. A new `infra-validate` workflow runs `terraform fmt -check` and `terraform validate`;
  three Terraform attribute groups were re-aligned for `fmt`. The manual container workflow now
  also starts the image and probes `/healthz`.
- README, START_HERE, AGENTS, implementation status and changelog were updated to say what has now
  been verified. Packaging-time publishing instructions were replaced by pointers to the
  verification records.

### After the first push

- The repository was created as `gandhiashutosh14/asterion-rehearsal` (the package's own
  distribution name), with the description and topics the package suggested, minus `aws` and
  `azure`, which would overstate a design-only cloud target.
- The test matrix passed on Python 3.11, 3.12 and 3.13 with no skips. The container workflow and
  the Terraform workflow were dispatched manually, since the latter's path filter does not fire on
  a repository's first push. Both passed. The results, with run links, are in
  `reports/verification/README.md`, and the infra README, cloud architecture and implementation
  status now cite them.
