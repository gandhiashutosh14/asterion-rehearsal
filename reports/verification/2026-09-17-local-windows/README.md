## Defects found and fixed before publishing

1. **Exported dossiers failed their own manifest on Windows.** `export_dossier` hashed the UTF-8
   text but wrote it in text mode, which turns `\n` into `\r\n` on Windows. Found by
   `test_html_escaping_and_export`. `src/asterion/reporting.py` now writes the exact hashed bytes.
   This is the only change under `src/`; Linux output is unchanged, which is why the shipped
   reference reports still verify and the evidence digests still match.
2. **Benchmark source hashes used backslash paths on Windows.** `scripts/benchmark.py` now records
   POSIX paths, so its source manifest compares across platforms.
3. **Helper scripts used the platform text encoding.** `browser_check.py`, `build_site.py`,
   `export_schemas.py`, `render_diagrams.py`, `verify_dossier.py` and `benchmark.py` now read and
   write UTF-8 with LF explicitly.
4. **Line endings.** A `.gitattributes` keeps LF on checkout, so committed dossier manifests and
   source hashes stay valid on Windows clones.
5. **Packaging.** `pyproject.toml` requires setuptools 77+ (needed for the SPDX `license` string)
   and declares project URLs, classifiers and the licence file.

Because `reporting.py` changed, its hash in `reports/reference/summary.json` (from the packaging
run) no longer matches the source. The shipped reference reports were kept as the packaging-time
record rather than regenerated; the fresh summary in this folder carries the current hashes.
